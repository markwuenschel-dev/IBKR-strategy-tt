01 — Executive assessment

synthesized from bound owner artifacts

A well-designed system whose enforcement has not kept pace with its design. The pure core is correct and the seams are well-chosen; almost every finding is about something the architecture asserts but nothing checks.

One immutable baseline, three hash-bound owner artifacts, every grade and score recomputed by the canonical verifiers rather than asserted. The health grade is D with a 92.5% weighted coverage and high confidence, capped by a verification baseline that a clean install cannot reproduce. Forty integrity candidates and seven architecture candidates converge on a single pattern: the four Protocol seams, the paper-trading safety claim, the line budget, the mission-test CI gate, and the working-orders guard are each stated in prose and enforced by nothing.

07 — Cross-cutting synthesis

convergent findings, not duplicate ownership

Load-bearing invariants are documented, not enforced

The ports contract, the paper-trading guard, the refresh-limit budget, the mission-test gate and the working-orders obligation are each asserted in a docstring or a comment and checked by no test, type, or lint rule. Two docstrings that justify design decisions are provably false: runner.py:209 claims one broad exception handler where there are eighteen, and harness.py:3 claims universal coverage that three test modules bypass.

Health · Integrity · Architecture

The environment, not the code, decides whether the suite runs

tzdata is undeclared while cli.py:36 evaluates a ZoneInfo lookup at import time, so a clean install of the declared dependencies fails at collection on any host without a system tz database. CI is green only because ubuntu-latest supplies one. Every dependency is an unpinned floor with no lock file, so the verification result is a property of the day it ran.

Health · Integrity

The largest adapter is the least verifiable, and that is a structural choice

scanner.py is 974 lines behind a correct two-method port, of which roughly 600 cannot be reached by any test because it calls its vendor loader directly instead of accepting it as a parameter, as the sibling broker adapter does. The uncovered region contains the line-budget enforcer, the leak paths, and both pure statistical functions.

Integrity · Architecture

Requested intent is substituted for observed fact at the money boundary

When the venue reports a fill with no quantity or price, the broker adapter substitutes the proposal's own quantity and limit price and writes them to the durable record with no marker. Partial fills are separately recorded as zero fills. The reviewer adapter refuses exactly this substitution and says why; the broker adapter does it where the fact is financial.

Integrity · Architecture

IBKR translation has no owner

The venue-status vocabulary is defined twice and already differs by one member; routing constants and expiry encoding are duplicated across the quote and trade paths, and the two contracts are not field-identical; a live vendor session travels between two adapters as an untyped keyword argument invisible to both their ports.

Integrity · Architecture

09 — Evidence certainty and gaps

confirmed
  • All five verification commands were executed in a byte-identical isolated copy; ruff check passed, ruff format --check failed on README.md, the mission test passed, the full suite errored at collection in a clean venv and passed 75/75 once tzdata was installed.
  • The SEI snapshot bound 886 measurements at this revision, 745 of them measured.
  • The engineering-intelligence artifact, its baseline pin and its index were minted, then re-read and rehashed through the canonical reader with the binding verified.
inferred
  • GitHub Actions' default Linux shell semantics underpin the mission-gate finding; the file content is verified and the piped-exit behaviour was reproduced locally, but not on GitHub's runners.
  • Severity rankings assume this system trades real money, per the live paper-account verification recorded in the README.
unknown
  • No claim about ib_async's real runtime behaviour could be closed: the library is not installed and CI never installs it, so the entire broker wire surface is asserted only against a hand-written stub.
  • Whether the two documents in docs/ are present deliberately as external reference material or by accident cannot be determined from the repository.
  • Coverage is a reachability argument from reading test doubles and import graphs, not a measured number; no coverage tooling is configured.
coverage gaps
  • The market-data adapter and the broker wire encoding were assessed statically only; no live TWS session exists.
  • Change-coupling, churn and hotspot analysis were unavailable because the working tree is not under version control.
  • SEI's change_discipline dimension scored 0 purely because there is no history to read, not as a judgment about commit practice.
